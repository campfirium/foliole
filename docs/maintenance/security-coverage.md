# Security coverage evidence

Run `node scripts/security/security-maintenance.mjs .tmp/artifacts/security-maintenance/coverage` from the checkout. Optional `--android-report FILE` and `--swift-report FILE` import explicitly chosen native reports; the command never searches for a convenient latest report. It writes `coverage.json` and separate raw production/full-lock npm audit responses. It queries package metadata, not user libraries, and does not update dependencies or run package install scripts.

The production npm hardening gate is unchanged. The additional full-lock audit includes development/build dependencies and retains their scope. An audit process exit of one can mean findings; transport failure, malformed/empty output, missing details and inconsistent zero-match output are errors. Reported npm parent dependency counts are not necessarily distinct vulnerabilities or shipped-runtime risks.

The repository-owned declaration in `scripts/security/security-coverage.mjs` lists npm runtime/build tools, selected Maven runtime/build graphs, both Swift graphs, embedded native components, Gradle, each build JDK/trust store, Node/npm, Electron/Capacitor, Xcode/Swift, Android SDK/Build Tools, all workflow action/reusable-workflow references and OS/WebView/WebKit responsibilities. Workflow YAML is parsed, retaining local, remote and unsupported dynamic references; malformed files are source errors. This does not change the deliberate Actions Dependabot exclusion.

A required observation must match candidate revision, input digest and environment, with an authoritative source and valid time. Automated advisory evidence expires after 26 hours; official reviews after 8 days. Missing, expired, mismatched, failed and unsupported required routes keep the aggregate incomplete. Known findings remain visible even when their old inputs cannot qualify the current candidate. A working-tree report cannot attest a frozen release candidate.

Native extractors now record the shared candidate/input receipt and recheck it after collection. A changed source cannot qualify the new report; earlier reports without this receipt remain unqualified. Their original scoped status, facts and raw report hash are retained. Swift resolution is not an official advisory review. Actual tool/vendor reviews, embedded binary identities and device OS observations need separately qualified evidence. The existing Scheduled Dev Quality workflow now has a separate 20-minute security job without full-admission dependencies. It prepares the actual Android graph, refreshes Maven/npm evidence and always attempts a revision-named artifact, including explicit setup failures. Its temporary continue-on-error boundary preserves existing full-quality/release admission while this report route is qualified; it does not turn the security result clean. Durable disposition/notifications and recurring official review remain separate integration steps; a real hosted run is required before declaring the schedule operational. A configuration or fixture does not prove that those routes have run.
