# SQLCipher security maintenance

Android's application dependency constraint and the iOS App's tracked Swift lock select SQLCipher 4.20.0. The Capacitor SQLite plugin retains ownership of its published dependency ranges; generated manifests and node_modules are not patched. This maintenance upgrade includes the vendor's 4.19 schema export quoting and invalid URI hexkey fixes, and the 4.20 SQLite 3.54.1 baseline. It does not enable encryption, change application keys or invoke a database migration.

For graph evidence use `node scripts/ios/swift-security-inventory.mjs <artifact-directory> --resolve`. For the native contracts run `npm run test:files -- scripts/ios/sqlcipher-security.test.mjs`. On macOS this first resolves the App against its tracked lock in the registered cache, then compiles a C contract against the actual resolved SQLCipher package's macOS framework, rather than system SQLite or a mock. It tests rejection of an invalid nonempty URI hexkey, safe export to a SQL-like schema alias, encrypted/wrong-key behavior, plaintext persistence, transactions, FTS5 and attached staging across process restarts. The Apple framework contract is not executed on non-macOS hosts; it does not attest Android JNI or an iPhone runtime.

For another native upgrade, retain old-version before/after evidence using disposable databases, prove old databases can be opened and written with the candidate, and verify rollback readability where required. Use the registered Android build and unsigned release bundle entry, inspect packaged AAR/native library identity, resolve the App Swift graph and run the applicable iOS runtime scenarios. A build or version string alone cannot prove database compatibility. Real device ABI, lifecycle and network coverage belongs to the existing trial batch.

Official sources: [SQLCipher 4.19 security fixes](https://www.zetetic.net/blog/2026/09/08/sqlcipher-4.19.0-release/), [SQLCipher 4.20 baseline and providers](https://www.zetetic.net/blog/2026/10/27/sqlcipher-4.20.0-release/). Android community builds use LibTomCrypt; Apple builds use Common Crypto. Do not infer a package's crypto provider from a different edition or operating system.
