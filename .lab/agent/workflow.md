# Agent Workflow Manual

## 台账规则
1. `.lab/agent/TODO.md` 是所有未完成工作的唯一真实来源，必须分为“待办”“待验证”“可选”三区。
2. `.lab/agent/DONE.md` 是已完成工作的追加式记录，不承载未完成项。
3. TODO / DONE 条目正文默认中文；仅代码标识、命令名、路径、协议字段保留英文。
4. 每条任务首标签只能是 `[auto]` 或 `[gate]`。
5. `[auto]` 仅用于可由 CLI / 脚本连续完成并自行验证的任务。
6. `[gate]` 仅用于必须人工观察、人工点击、外部确认或显式暂停等待的任务。
7. 若任务同时包含自动化实施与人工验收，必须先按执行模式拆开，禁止混写在一条里。
8. 当用户提供新任务、新反馈，或实施中发现结构性阻塞时，先更新 TODO，再实施或汇报。
9. 某条任务完成最小相关验证后，必须从 TODO 移除并迁入 DONE；若已实现但仍待人工确认，移动到“待验证”区。
10. “可选”区只允许放不改变当前主线验收口径、可独立验证回退的小任务。

## “继续”协议
1. 仅当新会话首条有效指令是“继续”时，读取 TODO / DONE 与最近提交记录恢复上下文。
2. 同一会话里再次说“继续”，只表示继续当前上下文，不重新抢占 TODO。
3. 触发恢复后，至少核对 `git log --oneline -n 5`，确认 TODO 首项没有被后续提交覆盖。
4. 在代码改动前，先向用户发“准备实施清单”：本轮拟做的 1 个最小任务、验收标准、不做项。
5. 用户未确认前，不按旧理解直接开工。
6. 例外：来源是 `agent loop` / `full-auto` / 无人值守自动执行，且待办首条为 `[auto]` 时，可直接实施，不输出等待确认话术。
7. 若待办首条为 `[gate]` 且人工暂时不可处理，可临时转做“可选”区第一条 `[auto]`，但一旦 gate 恢复可处理，必须回主线。

## 停车协议
1. 停车信号文件是 `.lab/agent/park.flag`；内容为 `PARK` 表示当前任务完成后停车。
2. 每完成一条任务、进入下一条前，必须检查停车信号。
3. 检测到停车信号后，只能输出当前进度、未提交改动与下一步建议，不能“顺手再做一条”。
4. 停车信号优先级高于 `[auto]` 可选任务和 agent loop。
5. 清除停车信号后，再按 TODO 主线或可选区规则继续。

## Windows 预览与同步
1. Windows 预览默认是否执行，只看 `.lab/agent/windows-preview.flag`，有效值仅 `ON` / `OFF`。
2. `ON`：每个任务在本地质量闸后默认继续执行 `npm run windows:preview`。
3. `OFF`：默认不执行 Windows 客户端联调，验证只要求本地 `lint` / `typecheck` / `test` 或相关最小子集。
4. 用户要求“打开 Windows 预览开关”时写入 `ON`；要求“关闭”时写入 `OFF`。
5. 即便开关为 `OFF`，用户若明确要求本次执行 Windows 验收，也可临时执行，但不改持久状态。
6. 对外宣称“Windows 客户端可见”前，必须回报实际命令与最终状态字段：`status: SYNCED` / `RESTARTED` / `DELIVERED`。
7. `windows:preview` 的约定流程是：先 `windows:sync`，再确认 Windows `electron:dev` 运行；若改动包含 `electron/**` 则重启客户端，否则走 HMR。

## 迭代日志与文档治理
1. 迭代日志只在提交前整理并落库，不为同一会话中的连续小改反复新增记录。
2. 日志文件固定在 `.lab/agent/iteration-log/entries/YYYYMMDD-HHMM-<slug>.md`。
3. 新增日志后，必须同步更新 `.lab/agent/iteration-log.md` 索引。
4. 历史大文件只能放 `.lab/agent/iteration-log/archive/`，不再继续追加。
5. 同一主题只能保留一个真相文件。
6. 新增文档时，必须说明替代了哪个旧文档，或为什么不能复用现有文档。
